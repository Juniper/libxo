The “xo-logger” Utility¶

The xo-logger utility is a command-line-compatible replacement for the traditional logger(1) utility, built on the libxo library. It reads a message, either from the command line, a file, or its standard input, and passes it to the system log module via libxo’s xo_syslog() function, generating an RFC 5424-style structured log message:

  % xo-logger 'disk failure on da0'

syslog:
  <13>1 2026-08-31T10:22:03.512-0400 myhost phil 4207 - - disk failure on da0

Every option below that also appears in the traditional logger(1) utility behaves the same way, so existing scripts that invoke logger can generally be switched over to xo-logger unchanged. The message argument’s libxo formatting is the one deliberate extension beyond that compatibility, described next.

Message Format and Arguments¶

Unlike stock logger(1), the message argument may use the libxo field-descriptor format string syntax described in Format Strings, consuming any trailing command line arguments as field values. This lets a single log message carry both a human-readable rendering and a set of structured, named fields:

  % xo-logger 'Disk {:disk} is at {:percent/%d}%\\n' /dev/da0 97

syslog:
  <13>1 2026-08-31T10:22:03.512-0400 myhost phil 4207 - \\
      [- disk="/dev/da0" percent="97"] Disk /dev/da0 is at 97%

If no format directives are needed, an ordinary string works fine, as in the first example above; xo-logger does not require the caller to opt into the extended syntax.

If a message argument is given on the command line, it takes precedence over --filename/-f; if neither is given, xo-logger reads lines from its standard input, one log message per line. This matches the way logger(1) chooses among its three input sources, except that logger(1) favors -f over a message argument, while xo-logger favors the message argument, since a format string with field values on the command line is otherwise indistinguishable from plain text.

Input Sources¶

--filename/-f reads the message from a file, instead of the command line, sending one log message per line:

% xo-logger --filename /var/log/build-errors.txt --tag builder

Each line of the file becomes an independent syslog message; none of the libxo field-descriptor handling is applied to file input, since there are no further command line arguments to supply field values.

When neither a message argument nor --filename is given, xo-logger reads from its standard input instead, again treating each line as a separate message:

% tail -F /var/log/build.log | xo-logger --tag builder

Priority: Facility and Severity¶

--priority/-p sets the facility and/or severity of the message, given together as a single facility.severity pair:

% xo-logger --priority local0.error \\
    'Disk {:disk} is at {:percent/%d}%\\n' /dev/da0 97

Either half of the pair may be omitted, in which case it defaults independently; local0 alone sets just the facility, while .error alone sets just the severity. With neither half given, xo-logger defaults to user.notice, the same default logger(1) uses. A purely numeric priority is also accepted, as is generated by the LOG_MAKEPRI() macro.

The complete set of recognized facility and severity names can be listed with --list-facilities and --list-severities:

% xo-logger --list-facilities
auth
authpriv
cron
...
% xo-logger --list-severities
emerg
alert
crit
...

Message Identity¶

--tag/-t marks every message with the given tag, which appears in the syslog output as the message’s APP-NAME:

% xo-logger --tag backup-cron 'nightly backup finished'

If --tag is not given, xo-logger defaults to the invoking user’s login name, falling back to “-” if that cannot be determined.

--hostname/-H overrides the HOSTNAME field of the message, which otherwise defaults to the local host’s name. This is useful when xo-logger is being used to relay messages on behalf of some other system:

% xo-logger --hostname sensor-42.example.com \\
    'Temperature {:temp/%d} out of range' 105

-i is accepted, for compatibility with logger(1)’s -i flag, but has no effect; the messages xo-logger generates always include a process ID in the PROCID field, so there is nothing extra for -i to turn on.

Echoing to Standard Error¶

--print/-s, in addition to the system log, prints the message to standard error, prefixed with the message’s tag, the same way logger(1)’s -s does:

% xo-logger --print --tag build 'compile failed'
build: compile failed

This is handy for interactive use, or when a script wants both a system log entry and immediate console feedback.

Remote Delivery¶

By default, xo-logger writes to the local system log socket, just like logger(1).

Giving --host/-h instead sends the message via UDP to that host:

% xo-logger --host loghost --tag backup 'Backup complete'

--host accepts either a hostname or an address, resolving a hostname to whichever address family responds; --inet4/-4 and --inet6/-6 restrict that resolution to IPv4 or IPv6 addresses only:

% xo-logger --inet6 --host loghost.example.com 'started'

A hostname may resolve to more than one address. By default only the first is used; --all-addresses/-A sends the message to every address the host resolves to:

% xo-logger --all-addresses --host loghost-cluster.example.com \\
    'cluster event'

--port/-P selects the destination port on --host, given as either a service name or a number, defaulting to 514, the standard syslog port:

% xo-logger --host loghost --port 1514 'started on alternate port'

An unrecognized service name falls back to 514, with a warning.

--source/-S binds the outgoing socket to a specific local address and port before sending, which is useful on multi-homed hosts where the log server expects traffic from a particular interface:

% xo-logger --host loghost --source 192.0.2.10:0 'started'

IPv6 source addresses must be bracketed, e.g. [::1]:1514.

A --host value that begins with / is treated instead as a filesystem path to an AF_LOCAL socket, such as /var/run/log, letting xo-logger target a non-default local socket the same way it targets a remote one:

% xo-logger --host /var/run/log.otherjail 'jail-local message'

This remote delivery support is implemented as a family of xo_log_set_* functions in the libxo library itself, documented in Handles, so other logging clients can be built on the same functionality without re-implementing DNS resolution or socket management.

Command Line Options¶

Usage: xo-logger [options] [message [arguments...]]
  --inet4 OR -4         Resolve --host to IPv4 addresses only
  --inet6 OR -6         Resolve --host to IPv6 addresses only
  --all-addresses OR -A Send to every address --host resolves to
  --filename <file> OR -f <file>
                        Read the message from <file>, one log message
                        per line; ignored if a message argument is given
  --hostname <name> OR -H <name>
                        Use <name> for the message's HOSTNAME field
  --host <host> OR -h <host>
                        Send the message to <host> via UDP, instead of
                        the local system log socket; <host> may also be
                        a filesystem path to an AF_LOCAL socket
  -i                    Accepted for compatibility; has no effect
  --port <port> OR -P <port>
                        Send to <port> on --host (service name or
                        number); defaults to 514
  --priority <fac.sev> OR -p <fac.sev>
                        Set facility and/or severity of the message;
                        defaults to 'user.notice'
  --print OR -s         Also print the message to standard error
  --source <addr:port> OR -S <addr:port>
                        Bind the outgoing socket to the given local
                        address and port before sending
  --tag <tag> OR -t <tag>
                        Mark every message with the given tag; defaults
                        to the invoking user's login name
  --list-facilities     List all valid logging facility names
  --list-severities     List all valid logging severity (level) names
  --help                Display this help text
  --version             Display version information

Example¶

% xo-logger 'Disk {:disk} is at {:percent/%d}%\\n' /dev/da0 97

% xo-logger -p local0.error -t diskmon \\
    'Disk {:disk} is at {:percent/%d}%\\n' /dev/da0 97

% xo-logger -h loghost -P 514 -t backup 'Backup complete'

% logger_input.sh | xo-logger -t backup
